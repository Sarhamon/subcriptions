# SubEco 발표 대본

> 구독 관리 트래커 · Spring Boot 4 학습 프로젝트 (1~14강)
> **발표 7~10분 + 질의응답 5분 / 팀원 5명 전원 발표**
> 슬라이드 번호는 `docs/index.html` 덱 기준. 각 절 끝의 `▶ 루브릭`은 어떤 채점 항목을 노리는지 표시.

## 발표 구성 & 타이밍 (총 ≈ 9분)

| 순서 | 발표자 | 담당 | 슬라이드 | 시간 |
|---|---|---|---|---|
| 1 | **이태경** | 서비스 기획·비즈니스 · 도메인 모델 · 예외처리 · 댓글 엔티티 | 1~3, 댓글 | 2:15 |
| 2 | **김세진** | 구독 CRUD (Service·Controller·PRG) · REST API | 4~5, REST | 2:15 |
| 3 | **이상윤** | 환율 서비스 · 문제 해결 · 테스트 코드 | 6~7, 테스트 | 2:15 |

## 1. 이태경 — 기획·비즈니스 · 도메인 · 예외처리 · 댓글

### [슬라이드 1 — 타이틀]
"안녕하세요, 저희 팀 프로젝트 **SubEco — 구독 관리 트래커**를 발표하겠습니다. 저는 기획과 도메인 설계를 맡은 이태경입니다."

### [슬라이드 2 — 서비스 소개 + 도메인]
"**한 줄로 말하면, 흩어진 구독 서비스의 결제일과 금액을 한 곳에서 관리해 주는 가계부형 대시보드입니다.**

- **타깃**: Netflix·Spotify·ChatGPT처럼 여러 구독을 동시에 쓰는 2030 사용자입니다. '내가 지금 몇 개를 결제 중이고, 다음 결제가 언제인지' 모르는 사람이 대상입니다.
- **수업 예제(Article 게시판)와의 차별점**: 단순 글 CRUD가 아니라, **결제 주기로 다음 갱신일을 자동 계산**하고, **외화 구독을 실시간 환율로 원화 환산**하며, **갱신 임박을 알려 주는** 도메인 로직이 핵심입니다.
- **비즈니스 가능성**: 갱신 임박 알림에 기반한 **광고·제휴 추천**(더 싼 요금제 안내), 안 쓰는 구독 정리로 비용을 줄여 주는 **구독 다이어트 코칭** 모델로 확장할 수 있습니다. 개인 자산관리 앱의 한 기능으로 붙이는 방향도 현실적입니다.

도메인은 **Subscription** 엔티티가 중심이고, 결제주기·통화·분류 태그를 **enum**으로 두었습니다. 특히 `BillingCycle` enum은 `addTo()` 메서드로 **날짜 계산 로직을 enum 안에 내장**해, 월/연 갱신 계산이 한 곳에 모이도록 설계했습니다."

### [슬라이드 3 — 예외 처리]
"존재하지 않는 구독에 접근하면 `SubscriptionNotFoundException`을 던지고, `@ControllerAdvice`인 **GlobalExceptionHandler**가 이를 받아 **404 상태 + 사용자용 에러 페이지**로 변환합니다. 잘못된 요청에 빈 화면이나 스택트레이스 대신 **친절한 안내 페이지**를 보여 주는 UX 배려입니다."

### [슬라이드 — 댓글 엔티티]
"마지막으로 14강 범위인 **댓글(메모) 기능**의 토대를 만들었습니다. `Comment` 엔티티가 구독을 **단방향 `@ManyToOne`**으로 참조하고, `CommentRepository`의 `findBySubscriptionId`로 구독별 메모를 조회합니다. 양방향 대신 단방향을 택해 엔티티를 단순하게 유지했습니다.

다음은 CRUD와 REST API를 맡은 김세진 입니다."

> ▶ 루브릭: **서비스 독창성·기획력(12)**, **비즈니스 가능성(8)**, **디테일·UX(10)** 일부, **소스흐름 보고서(20)**(어노테이션 역할 설명)

## 2. 김세진 — 구독 CRUD · REST API

### [슬라이드 4 — SubscriptionService]
"CRUD를 맡은 김세진입니다. 비즈니스 로직은 **SubscriptionService**에 모았습니다. 생성·조회·수정·삭제 **네 가지가 모두 동작**하며,

- 클래스에는 기본 `@Transactional(readOnly = true)`를 걸고, **변경 메서드만 `@Transactional`로 덮어썼습니다.**
- **수정은 `save()` 호출 없이 더티 체킹**으로 반영됩니다. 트랜잭션 안에서 엔티티 필드만 바꾸면 JPA가 변경을 감지해 UPDATE를 날립니다.
- 조회 시점에 **지난 갱신일을 오늘 이후까지 자동으로 밀어 주는** 보정 로직도 서비스에 있습니다."

### [슬라이드 5 — Controller · Form · PRG]
"화면용 컨트롤러 `SubscriptionController`는 7개 URL로 목록·등록·상세·수정·삭제를 라우팅합니다.

- 입력은 엔티티가 아니라 **`SubscriptionForm` DTO**로 받아 `toEntity()`로 변환합니다. 엔티티를 직접 폼에 노출하지 않는 안전한 구조입니다.
- 저장·수정·삭제 같은 POST 처리 뒤에는 **PRG 패턴**으로 `redirect:` 시켜, 새로고침 시 **중복 저장을 방지**합니다."

### [슬라이드 — REST API]
"여기에 더해 **REST API**를 별도로 구현했습니다. **`@RestController`인 `SubscriptionApiController`**가 `/api/subscriptions` 경로로 **GET·POST·PATCH·DELETE 5개 엔드포인트**를 제공하고, 반환 객체는 Jackson이 **JSON으로 직렬화**합니다.

중요한 점은, 화면용 404는 HTML 페이지지만 **REST는 컨트롤러 로컬 `@ExceptionHandler`로 `{\"message\": ...}` JSON 404**를 따로 응답한다는 겁니다. 같은 예외라도 클라이언트에 맞는 형식으로 돌려줍니다. *(시연/캡처: `GET /api/subscriptions`, 없는 id 404 JSON)*

다음은 환율 연동과 테스트를 맡은 이상윤 입니다."

> ▶ 루브릭: **CRUD 기능 완성도(20)**, **REST API/JSON(10)** — `@RestController` 2개 이상·JSON 정상·캡처 포함

## 3. 이상윤 — 환율 서비스 · 문제 해결 · 테스트

### [슬라이드 6 — ExchangeRateService]
"환율과 테스트를 맡은 이상윤입니다. 외화 구독을 원화로 보여 주려고 **외부 환율 API**를 연동했습니다.

- 매 요청마다 호출하면 느리니, 앱 시작 시 `@PostConstruct`로 한 번 불러와 **`ConcurrentHashMap`에 캐싱**하고, `@Scheduled` cron으로 **매일 자정 갱신**합니다.
- API가 실패해도 **`Currency` enum의 폴백 환율**로 앱이 계속 동작합니다. JPY는 직접 환율 대신 **USD 기준 교차 환율**로 계산합니다."

### [슬라이드 7 — 문제 해결]
"개발 중 실제로 막혔던 문제 두 가지입니다.

1. 처음 쓴 **Frankfurter API가 KRW를 지원하지 않아** JSON 대신 HTML 에러를 반환했습니다. 네트워크 문제인 줄 알고 핫스팟까지 바꿔 봤지만, 원인은 **ECB 데이터에 원화가 없어서**였고, **KRW를 지원하는 open.er-api.com으로 교체**해 해결했습니다.
2. Spring Boot 4 환경에서 `RestClient.Builder` 빈 자동 등록과 커스텀 record 역직렬화가 말썽이라, **응답을 `Map<String,Object>`로 받는 방식**으로 바꿔 의존성 문제를 한 번에 없앴습니다."

### [슬라이드 — 테스트 코드]
"품질 확인을 위해 **테스트 9개**를 작성했고 전부 통과합니다. **MockMvc로 REST API 통합 테스트 6개**(목록·단건·404·생성·수정·삭제), **댓글 리파지터리 테스트 2개**, 컨텍스트 로드 1개입니다.

테스트 작성 중에도 문제가 있었는데, **Spring Boot 4는 Jackson 3와 모듈형 스타터를 써서** `ObjectMapper`가 `tools.jackson` 패키지로, `@AutoConfigureMockMvc`도 경로가 바뀌어 있었습니다. 추측 대신 **클래스패스 jar를 직접 열어 실제 패키지를 확인**해 import를 교정했습니다.

다음은 화면 데이터 가공을 맡은 김준아 입니다."

> ▶ 루브릭: **소스흐름 보고서(20)** — *실제 오류 2건 이상·해결 과정* 충족, **REST API/JSON(10)** 신뢰성 보강

## 4. 김준아 — SubscriptionView DTO · 홈 대시보드

### [슬라이드 8 — SubscriptionView]
"데이터 가공을 맡은 김준아입니다. Mustache 템플릿은 로직을 못 쓰기 때문에, **화면에 필요한 모든 계산을 `SubscriptionView` 생성자에서 끝냅니다.**

`displayPrice`(외화면 원화 병기), `daysText`('오늘' / 'N일 후'), `dueSoon`(임박 배지), `colorClass`(카드 색상), `emoji`(서비스 아이콘), `monthlyKrw`(연간이면 ÷12) 등을 미리 만들어 두고, 템플릿은 **출력만** 합니다. 불변 객체라 안전하고 디버깅도 쉽습니다."

### [슬라이드 9 — 홈 대시보드]
"홈은 `HomeController`가 구독 전체를 모아 **월 합산 지출, 이번 달 갱신 건수, 7일 이내 임박 건수, 자동결제 개수**를 집계하고, **갱신일 순으로 정렬해 임박 4건**을 보여 줍니다. '내 구독을 한눈에'라는 기획 의도를 그대로 화면에 옮긴 부분입니다.

다음은 UI와 뷰를 맡은 이예은 입니다."

> ▶ 루브릭: **디테일·UX(10)**, **소스흐름 보고서(20)** (계층 분리 설명)

## 5. 이예은 — UI·UX · Mustache · 마무리

### [슬라이드 10 — UI·디자인]
"UI를 맡은 이예은입니다. 다크 테마에 **CSS 변수로 색상을 일원화**하고, 카드 상단 색 스트라이프와 서비스별 이모지로 한눈에 구분되게 했습니다.

**사용자 배려(UX)**도 신경 썼습니다. 구독이 하나도 없으면 **빈 목록 안내**를 보여 주고, 잘못된 주소로 들어오면 **커스텀 404 페이지**로 안내하며, 갱신이 임박하면 카드에 **강조 배지**를 띄웁니다."

### [슬라이드 11 — Mustache 템플릿]
"뷰는 **Mustache 서버사이드 렌더링**입니다. 목록·등록·수정·상세·환율·에러 페이지를 템플릿으로 나누고, 공통 헤더/푸터는 **파셜로 재사용**합니다. 로직이 없는 템플릿이라, 모든 계산은 앞서 본 `SubscriptionView`가 담당합니다."

### [슬라이드 12 — 마무리]
"정리하면, 저희는 1~14강 범위의 **MVC·JPA·CRUD·REST API·JSON**을 실제 구독 관리라는 주제로 구현했고, **자동 갱신일 계산·실시간 환율·대시보드**로 수업 예제와 차별화했습니다. 들어 주셔서 감사합니다. 질문 받겠습니다."

> ▶ 루브릭: **디테일·UX(10)**(빈 목록·오류 안내), **발표 전달력(10)**(전원 참여·마무리)
