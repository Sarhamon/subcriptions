01서비스 기획 — 아이디어 · 비즈니스

1.1 서비스 소개

SubEco — 흩어진 구독 서비스의 결제일·금액·통화를 한 곳에서 관리해 주는 가계부형 구독 대시보드입니다.
  • 타깃 사용자 — Netflix·Spotify·ChatGPT 등 여러 구독을 동시에 쓰는 2030 세대. "지금 몇 개를, 얼마에, 언제 결제 중인지" 파악하지 못하는 사람.
  • 핵심 기능 — 구독 등록/조회/수정/삭제, 결제주기 기반 다음 갱신일 자동 계산, 외화 구독의 실시간 환율 원화 환산, 갱신 임박 알림, 월 합산 지출 대시보드.

1.2 기획 배경 — 왜 필요한가, 수업 예제와 무엇이 다른가

구독 경제가 커지면서 한 사람이 동시에 5~10개의 구독을 쓰는 일이 흔해졌습니다. 그러나 결제일이 제각각이라 "이번 달에 얼마가 빠져나가는지", "안 쓰는 구독이 자동결제되고 있지는 않은지"를 한눈에 보기 어렵습니다. SubEco는 이 문제를 해결합니다.

구분수업 예제 (Article 게시판)SubEco
데이터 성격정적인 글(제목·본문)날짜·금액·통화를 가진 계산 대상
핵심 로직단순 저장·조회갱신일 자동 계산 · 환율 환산 · 임박 판별
부가 가치없음(CRUD 자체가 목적)"언제·얼마" 인사이트 제공

1.3 사용 시나리오

  1. 사용자가 Netflix·ChatGPT Plus 등 자신의 구독을 등록한다(서비스명·금액·통화·주기·시작일·태그).
  2. 홈 대시보드에서 월 합산 지출(원화 환산)과 7일 이내 갱신 예정 목록을 확인한다.
  3. 외화 구독(USD/JPY)은 실시간 환율로 환산된 원화가 함께 표시된다.
  4. 갱신이 임박한 구독은 카드에 강조 배지로 알려 준다.
  5. 더 이상 쓰지 않는 구독은 삭제해 고정비를 정리한다.

1.4 비즈니스 가능성

  • 수익 모델 — 갱신 임박 시점에 더 저렴한 요금제·대체 서비스를 안내하는 제휴/광고 추천, 안 쓰는 구독 정리를 돕는 구독 다이어트 코칭(프리미엄).
  • 확장 방향 — 사용자 인증 연동(개인별 구독함), 카드 명세서 연동 자동 등록, 가족 공유 구독 분담 계산.
  • 사회적 가치 — 불필요한 자동결제로 인한 고정비 누수를 줄여 합리적 소비를 돕는다.

03도메인 모델 설계

3.1 Subscription 엔티티

구독 1건을 표현하는 핵심 엔티티. setter를 열지 않고 빌더 생성 + 의도가 드러나는 메서드(updateDetails, slideToNextCycle)로만 상태를 바꾼다.

// 결제주기 기반 다음 갱신일 = 시작일 + 주기
public LocalDate getNextRenewalDate() {
    return billingCycle.addTo(startedAt);
}

3.2 enum에 로직 내장 — BillingCycle / Currency / Tag

  • BillingCycle(MONTHLY/YEARLY) — addTo(LocalDate)로 날짜 계산 로직을 enum 안에 캡슐화(switch 표현식).
  • Currency(KRW/USD/JPY) — 표시 라벨 + 폴백 환율 보유. 환율 API 실패 시 사용.
  • Tag(ENTERTAINMENT/MUSIC/AI/PRODUCTIVITY/GAME/DEV) — 분류용. @ElementCollection으로 저장.

3.3 Comment 엔티티 (14강)

구독에 메모(댓글)를 남기는 도메인. 구독 → 댓글 단방향 @ManyToOne만 두어 엔티티를 단순하게 유지하고, 조회는 리파지터리 메서드 쿼리로 해결한다.

@ManyToOne
@JoinColumn(name = "subscription_id", nullable = false)
private Subscription subscription;   // nickname · body

3.4 DTO — 입력/출력 분리

DTO방향역할
SubscriptionForm입력폼/JSON 입력 바인딩 → toEntity()로 엔티티 변환
SubscriptionView출력화면·JSON에 필요한 모든 값을 생성자에서 미리 계산한 불변 객체
Mustache는 로직을 쓸 수 없으므로 displayPrice, daysText, dueSoon, colorClass, emoji, monthlyKrw 등 화면 계산을 모두 SubscriptionView 생성자에서 끝낸다. 템플릿은 출력만 담당.

04CRUD 기능 설계

4.1 SubscriptionService — 트랜잭션 전략

@Service
@Transactional(readOnly = true)   // 클래스 기본: 읽기 전용
public class SubscriptionService {
    @Transactional                 // 변경 메서드만 쓰기 트랜잭션
    public Subscription create(SubscriptionForm form) { ... }
}

읽기 전용 트랜잭션은 성능 이점과 함께 조회 메서드에서의 실수 변경을 예방한다. 단, findAll/findById는 조회 시 갱신일을 보정·저장하므로 쓰기 트랜잭션으로 둔다.

4.2 갱신일 자동 보정

// 지난 갱신일을 오늘 이후가 될 때까지 주기를 밀어준다
while (!subscription.getNextRenewalDate().isAfter(today)) {
    subscription.slideToNextCycle();
}

별도 스케줄러 없이 조회 시점에 실시간 보정해, 며칠을 방치해도 항상 정확한 미래 갱신일을 반환한다.

4.3 더티 체킹 기반 update

@Transactional 범위에서 영속 엔티티의 필드를 바꾸면 JPA가 변경을 감지해 커밋 시 자동 UPDATE를 실행한다. save() 호출이 없어 코드가 간결하다.

4.4 메서드 요약

메서드역할특이사항
findAll(tag)전체/태그 조회갱신일 보정 + 태그 필터
findById(id)단건 조회없으면 404 예외
create(form)신규 저장Form → Entity 변환

4.5 화면 컨트롤러 · PRG 패턴

SubscriptionController는 /subscriptions 아래 7개 엔드포인트(목록·등록폼·저장·상세·수정폼·수정·삭제)를 제공한다. HTML form은 GET/POST만 지원하므로 수정·삭제도 POST로 받고, 처리 후 PRG 패턴으로 redirect: 시켜 새로고침 중복 제출을 막는다. 입력은 엔티티가 아닌 SubscriptionForm DTO로 받아 엔티티 노출을 막는다.

05REST API / JSON 설계

@RestController인 SubscriptionApiController가 /api/subscriptions 경로로 JSON CRUD를 제공한다. 반환 객체는 Jackson이 자동으로 JSON 직렬화하며, 읽기 응답은 화면과 동일한 SubscriptionView를 재사용한다.

5.1 엔드포인트

메서드경로응답
GET/api/subscriptions200 · 구독 목록 JSON 배열
GET/api/subscriptions/{id}200 · 단건 JSON (없으면 404 JSON)
POST/api/subscriptions201 · 생성된 구독 JSON
PATCH/api/subscriptions/{id}200 · 수정된 구독 JSON
DELETE/api/subscriptions/{id}204 · 본문 없음

5.2 응답 예시

// GET /api/subscriptions/1
{"id":1,"serviceName":"Netflix","price":17000,"currency":"KRW",
 "billingCycle":"MONTHLY","displayPrice":"17,000 원","daysText":"27일 후",
 "dueSoon":false,"tags":["ENTERTAINMENT"], ...}

// GET /api/subscriptions/9999  → 404
{"message":"구독 정보를 찾을 수 없습니다. (id=9999)"}

5.3 REST 전용 JSON 404 — 컨트롤러 로컬 예외 핸들러

전역 GlobalExceptionHandler는 화면용 error/404 HTML 뷰를 반환한다. 이를 REST에 그대로 적용하면 JSON 대신 HTML이 나가므로, REST 컨트롤러 안에 컨트롤러 로컬 @ExceptionHandler를 두어 같은 예외를 JSON 404로 응답한다(지역 핸들러가 전역보다 우선).

검증: curl로 목록·단건·생성(201)·수정(200)·삭제(204)·404(JSON) 전 케이스 확인 완료. 제출 시 브라우저/Postman 응답 캡처를 첨부할 것.

06환율 연동 설계

ExchangeRateService가 외화 구독을 원화로 환산한다.

  • @PostConstruct로 앱 시작 시 1회 호출 → ConcurrentHashMap 캐싱, @Scheduled(cron="0 0 0 * * *")로 매일 자정 갱신.
  • API 실패 시 try/catch로 Currency enum 폴백 환율 유지 → 앱 무중단.
  • JPY는 직접 환율 대신 USD 기준 교차 환율(KRW/USD ÷ JPY/USD)로 계산.
  • RestClient로 호출하고 응답을 Map<String,Object>로 받아 역직렬화 문제를 회피.

08발생한 문제 & 해결 과정

① 환율 API가 KRW 미지원 — JSON 대신 HTML 에러 반환외부 API네트워크

현상 Frankfurter API 호출 시 text/html 에러 페이지가 와 파싱 실패. 핫스팟으로 바꿔도 동일.

원인 네트워크가 아니라 데이터 소스(ECB)에 원화(KRW)가 없어서였음.

해결 KRW 포함 170개 통화를 지원하는 open.er-api.com으로 교체.

② Jackson record 역직렬화 / unknown property 위험Jackson설계

현상 커스텀 record로 응답 매핑 시 생성자 접근·미지정 필드 오류 가능성.

해결 응답을 Map<String,Object> + ParameterizedTypeReference로 받아 unknown property 개념 자체를 제거. 커스텀 record·Jackson 직접 import 불필요.

③ Spring Boot 4에서 RestClient.Builder 빈 미등록 → 기동 실패런타임Spring Boot 4

현상 생성자에 RestClient.Builder 주입 시 UnsatisfiedDependencyException으로 서버가 뜨지 않음.

해결 빈 주입 대신 RestClient.create()로 직접 생성 — 자동 구성 의존을 제거.

④ REST 테스트 작성 시 import 패키지가 달라짐 (Jackson 3 · 모듈형 스타터)컴파일Spring Boot 4

현상 com.fasterxml.jackson.databind, ...autoconfigure.web.servlet 패키지를 찾을 수 없다는 컴파일 오류 4건.

원인 Boot 4는 Jackson 3(tools.jackson)과 모듈형 스타터를 채택 → @AutoConfigureMockMvc가 org.springframework.boot.webmvc.test.autoconfigure로 이동.

해결 추측 대신 클래스패스 jar 내부를 직접 확인해 실제 패키지로 import 교정 → 테스트 9개 전부 통과.

9.2 향후 개선 방향

  • 사용자 인증(Security) — 구독을 계정에 연결해 개인화 목록 제공.
  • 댓글 기능 완성 — 현재 엔티티·리파지터리까지(14강). 컨트롤러·서비스·UI로 확장(15강 이후).
  • 알림 — 갱신 N일 전 이메일/푸시(Spring Scheduler 활용).
  • 페이지네이션 — 구독이 많아지면 Pageable 기반 페이징과 쿼리 단계 집계.

9.3 마무리

SubEco는 1~14강의 MVC·JPA·CRUD·REST API·JSON을 실제 구독 관리라는 주제로 구현하면서, 갱신일 자동 계산·실시간 환율·대시보드로 수업 예제와 차별화했다. 모든 계층이 책임을 분리해, 한 부분이 바뀌어도 영향이 최소화되는 구조를 갖췄다.
