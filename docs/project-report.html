프로젝트 개요

무엇을 만들었나

Netflix, Spotify, ChatGPT Plus 등 여러 구독 서비스의 갱신일, 금액, 결제 주기, 자동결제 여부를 등록·조회·수정·삭제할 수 있는 개인용 웹 애플리케이션입니다.

홈 대시보드에서 이번 달 갱신 건수, 7일 이내 갱신 예정 목록, 월 합산 원화 지출을 한눈에 확인할 수 있으며, 외부 환율 API를 연동하여 USD·JPY 결제 금액을 자동으로 원화로 환산합니다.

발생한 문제 & 해결 과정
1
Jackson Record 역직렬화 실패 — private record
컴파일/런타임 오류 Jackson

현상

환율 API 응답 JSON을 Java record로 역직렬화할 때 예외 발생. 응답 자체는 정상이었지만 파싱 불가.

com.fasterxml.jackson.databind.exc.InvalidDefinitionException: Cannot construct instance of `ExchangeRateService$FrankfurterResponse` (no Creators, like default constructor, exist)

원인

ExchangeRateService 내부에 private record FrankfurterResponse(...)로 선언했기 때문. private 중첩 record는 Jackson이 canonical constructor에 접근할 수 없어 인스턴스를 생성하지 못함.

해결

// private 제거 → package-private으로 변경 record FrankfurterResponse(String base, String date, Map<String, BigDecimal> rates) {}
2
Frankfurter API — KRW 미지원으로 HTML 에러 페이지 반환
외부 API 네트워크

현상

api.frankfurter.app/latest?from=USD&to=KRW,JPY 호출 시 JSON이 아닌 HTML 반환. 학교 Wi-Fi는 물론 모바일 핫스팟에서도 동일한 오류 발생.

UnknownContentTypeException: Could not extract response: no suitable HttpMessageConverter found for response type [ExchangeRateService$FrankfurterResponse] and content type [text/html;charset=UTF-8]

원인 분석 과정

처음에는 학교 네트워크 프록시가 HTTPS 요청을 가로채 HTML 오류 페이지를 반환하는 것으로 추정. 핫스팟으로 전환했으나 동일 오류 재현 → 네트워크 문제가 아님을 확인.

원인은 Frankfurter API의 데이터 소스에 있었음. Frankfurter는 ECB(유럽중앙은행) 환율 데이터를 사용하며, ECB는 약 30개 통화만 게시함. KRW(한국 원)은 ECB 데이터셋에 포함되지 않기 때문에 to=KRW 파라미터에 대해 HTML 에러 페이지를 반환.

💡 ECB 지원 통화 예시: USD, EUR, JPY, GBP, CHF, AUD, CAD, CNY, THB 등 (~32개) KRW, INR, VND 등 아시아 통화 다수 미지원

해결 — ExchangeRate-API로 교체

// 변경 전 (Frankfurter — KRW 미지원) private static final String API_URL = "https://api.frankfurter.app/latest?from=USD&to=KRW,JPY"; // 변경 후 (open.er-api.com — KRW 포함 170개 통화, 무료, API 키 불필요) private static final String API_URL = "https://open.er-api.com/v6/latest/USD";

카드 정렬 불일치 — 서비스명·금액 길이 차이로 갱신일 위치가 어긋남
CSS/UI

현상

구독 목록 카드 그리드에서 서비스명이 길거나 금액(환산 원화 포함)이 2줄로 늘어나는 경우, 카드 하단의 갱신일·자동결제 배지가 카드마다 다른 높이에 위치하여 시각적으로 어긋남.

원인

카드 내부가 flex-direction: column인데, 하단 요소(.card-div)에 고정 위치 지정이 없어 내용 높이에 따라 자연스럽게 밀려 내려감. 카드 높이는 동일하지만 내용물 높이가 달라 빈 공간 분포가 불균일.

해결

/* margin-top: auto → flex 컨테이너에서 가용 공간을 위쪽으로 밀어냄 → 하단 요소가 항상 카드 바닥에 고정됨 */ .card-div { margin-top: auto; margin-bottom: 12px; }
4
Jackson ObjectMapper 직접 import 시 컴파일 오류
컴파일 오류 의존성

현상

HTML 응답 문제를 우회하려고 RestClient로 Raw String을 받은 뒤 ObjectMapper로 직접 파싱하는 방식을 시도. import com.fasterxml.jackson.databind.ObjectMapper 추가 후 빌드 실패.

error: package com.fasterxml.jackson.databind does not exist import com.fasterxml.jackson.databind.ObjectMapper; ^

원인

Jackson은 Spring Boot의 transitive dependency로 런타임에는 존재하지만, build.gradle에 직접 선언되지 않아 컴파일 클래스패스에 노출되지 않음.

해결

직접 import 방식 자체를 포기. Spring이 내부적으로 Jackson을 사용하는 MappingJackson2HttpMessageConverter를 구성하는 방식으로 변경. 이후 ExchangeRate-API 교체로 근본 원인(HTML 응답)이 해소되어 문제 전체 해결.

현상

홈 페이지를 대시보드로 개편하면서 갱신 임박 목록을 홈으로 이동했음에도, SubscriptionController에 기존 upcoming·hasUpcoming 모델 속성이 그대로 남아 구독 목록 페이지에도 배너가 이중으로 렌더링됨.

7
Spring Boot 4에서 RestClient.Builder 빈 자동 등록 안 됨 → 앱 기동 실패
런타임 오류 Spring Boot 4

현상

ExchangeRateService 생성자에 RestClient.Builder를 주입하도록 변경한 뒤 앱 기동 시 UnsatisfiedDependencyException 발생, 서버가 시작되지 않음.

Error creating bean with name 'exchangeRateService': Unsatisfied dependency expressed through constructor parameter 0: No qualifying bean of type 'org.springframework.web.client.RestClient$Builder' available: expected at least 1 bean which qualifies as autowire candidate.

원인

Spring Boot 3.2에서 RestClientAutoConfiguration이 도입되어 RestClient.Builder 프로토타입 빈이 자동 등록되지만, 이 프로젝트의 Spring Boot 4 환경에서는 해당 자동 구성이 활성화되지 않음. (spring-boot-starter-webmvc 스타터가 RestClientAutoConfiguration 조건을 충족하지 못할 가능성)

해결

RestClient.Builder 주입 방식 자체를 포기하고, 아래 문제 8의 Map<String, Object> 역직렬화 방식으로 전환하여 빈 주입이 필요 없도록 구조를 변경.

// 변경 전 — 빈 주입 필요 public ExchangeRateService(RestClient.Builder restClientBuilder) { this.restClient = restClientBuilder.build(); } // 변경 후 — 빈 주입 불필요 private final RestClient restClient = RestClient.create();
8
커스텀 record 역직렬화 시 Jackson unknown property 오류 가능성 해소
Jackson 설계 개선

배경

ExchangeRate-API 응답에는 result, provider, base_code, time_last_update_utc 등 다수의 필드가 포함됨. 커스텀 record ExchangeRateResponse(Map<String, BigDecimal> rates)에는 rates만 선언되어 있어, Jackson 기본 설정(FAIL_ON_UNKNOWN_PROPERTIES = true)에서는 역직렬화 실패 가능성이 존재함.

@JsonIgnoreProperties(ignoreUnknown = true)로 해결 가능하나, 이는 Jackson 어노테이션 직접 import가 필요하고, 이 프로젝트에서는 Jackson이 compile classpath에 직접 노출되지 않아 컴파일 오류를 유발함.

해결 — Map<String, Object> + ParameterizedTypeReference

응답 전체를 Map<String, Object>로 받으면 Jackson은 모든 키를 Map 엔트리로 저장하므로 unknown property 개념 자체가 사라짐. 커스텀 record 불필요, Jackson 직접 import 불필요.

// 변경 전 — 커스텀 record, unknown property 오류 위험 record ExchangeRateResponse(Map<String, BigDecimal> rates) {} ExchangeRateResponse response = restClient.get() .uri(API_URL) .retrieve() .body(ExchangeRateResponse.class); // 변경 후 — Map<String, Object>, 어떤 응답 구조에도 안전 private static final ParameterizedTypeReference<Map<String, Object>> RESPONSE_TYPE = new ParameterizedTypeReference<>() {}; Map<String, Object> body = restClient.get() .uri(API_URL) .header("Accept", "application/json") .retrieve() .body(RESPONSE_TYPE); Map<String, Object> rates = (Map<String, Object>) body.get("rates"); BigDecimal krwPerUsd = new BigDecimal(rates.get("KRW").toString());
💡 ParameterizedTypeReference는 org.springframework.core 패키지 소속으로 Jackson 직접 의존 없이 사용 가능. toString() 경유 BigDecimal 변환으로 부동소수점 정밀도 손실도 방지.
9
REST API 테스트 작성 — Spring Boot 4에서 테스트 import 패키지가 달라짐
컴파일 오류 Spring Boot 4

현상

/api/subscriptions REST API를 MockMvc로 검증하는 통합 테스트를 작성하고 ./gradlew test 실행 시 컴파일 단계에서 4건의 "cannot find symbol" 오류 발생.

error: package com.fasterxml.jackson.databind does not exist import com.fasterxml.jackson.databind.ObjectMapper; error: package org.springframework.boot.test.autoconfigure.web.servlet does not exist @AutoConfigureMockMvc

원인

이 프로젝트는 Spring Boot 4.0.6 + 모듈형 스타터(spring-boot-starter-webmvc-test)를 사용. Boot 4는 Jackson 3을 채택해 ObjectMapper가 com.fasterxml.jackson이 아닌 tools.jackson 패키지로 이동했고, @AutoConfigureMockMvc도 모듈화로 패키지 경로가 바뀜.

해결 — 클래스패스 jar에서 실제 패키지 확인 후 import 교정

// 변경 전 (Spring Boot 3 / Jackson 2 기준) import com.fasterxml.jackson.databind.ObjectMapper; import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc; // 변경 후 (Spring Boot 4 / Jackson 3) import tools.jackson.databind.ObjectMapper; import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc; // MockMvc 본체(org.springframework.test.web.servlet.*)는 그대로
💡 추측으로 import를 고치지 않고, Gradle 캐시의 jar 내부(unzip -l)에서 실제 클래스 경로를 찾아 교정 → 최종 9개 테스트 전부 통과(REST 6 · 댓글 리파지터리 2 · contextLoads 1).
주요 설계 결정
SubscriptionView — 불변 렌더링 DTO

Mustache 템플릿은 로직을 갖지 않으므로, 화면에 필요한 모든 값(displayPrice, daysText, colorClass, emoji, monthlyKrw 등)을 SubscriptionView 생성자에서 한 번에 계산해 저장. 템플릿은 단순 변수 출력만 담당하여 테스트·디버깅이 용이.

ExchangeRateService — ConcurrentHashMap 캐싱 + @Scheduled

매 페이지 요청마다 외부 API를 호출하지 않고, 앱 시작 시 @PostConstruct로 초기 로딩 후 매일 자정 @Scheduled(cron = "0 0 0 * * *")으로 갱신. API 실패 시에는 Currency enum에 하드코딩된 폴백 환율을 유지하여 앱이 계속 동작.

BillingCycle enum에 날짜 계산 로직 내장

addTo(LocalDate from) 메서드를 enum 안에 두어 결제 주기 추가 로직이 한 곳에 집중. 새 주기(분기·반기 등)가 생겨도 enum 케이스와 메서드만 추가하면 됨.

JPY 환율 교차 환율(Cross Rate)로 계산

환율 API가 USD 기준 KRW·JPY를 반환하면, JPY→KRW 직접 환율 대신 KRW/USD ÷ JPY/USD로 교차 환율을 계산해 저장. API 호출 횟수를 최소화하면서 정확한 환산이 가능.

REST API — 컨트롤러 로컬 예외 핸들러로 JSON 404 분리

기존 GlobalExceptionHandler(@ControllerAdvice)는 error/404 HTML 뷰를 반환하므로 REST 엔드포인트에 그대로 적용하면 JSON 대신 HTML이 응답됨. SubscriptionApiController 안에 컨트롤러 로컬 @ExceptionHandler를 두어, 같은 예외에 대해 REST는 {"message": …} JSON 404로 응답. 컨트롤러 로컬 핸들러가 @ControllerAdvice보다 우선하므로 MVC 흐름은 그대로 유지.

댓글(Comment) — 단방향 @ManyToOne

댓글은 Subscription을 @ManyToOne으로만 참조하고, 구독 쪽에는 컬렉션을 두지 않음. 엔티티를 단순하게 유지하고 양방향 동기화 부담을 피하기 위한 선택. 구독별 조회는 CommentRepository.findBySubscriptionId(id) 메서드 쿼리로 해결.
